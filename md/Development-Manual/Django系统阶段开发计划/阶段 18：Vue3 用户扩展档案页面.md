## 阶段导语

本阶段是合辑的收尾篇。阶段 17 已将门店、课程、动作及我的收藏接入前端，本阶段沿用同一套 API 封装与单文件组件（Single-File Component，SFC）范式，新增「我的档案」页面，对接后端的 `GET/PUT /api/profile/me/`，使当前登录用户可查看并修改自身的扩展档案信息。

## 2. 档案接口封装

### 2.1 新增 `frontend/src/api/profile.js`

新建文件：

```text
frontend/src/api/profile.js
```

写入：

```javascript
import request from "../utils/request"

export function getMyProfileApi() {
  return request.get("/profile/me/")
}

export function updateMyProfileApi(data) {
  return request.put("/profile/me/", data)
}
```

该文件对应的后端接口：

| 方法 | 路径 | 参数 | 返回说明 |
|------|------|------|----------|
| GET | `/api/profile/me/` | 无 | 当前登录用户的扩展档案 |
| PUT | `/api/profile/me/` | 请求体 `data` | 更新并返回当前登录用户的扩展档案 |

**要点**：

- **要点**：读写接口共用 `/profile/me/` 路径，以请求方法区分语义。
- **要点**：接口不带用户 ID 参数，用户身份由后端依据 token 解析。

<script setup>
import { onMounted, reactive, ref } from "vue"

import {
  getMyProfileApi,
  updateMyProfileApi
} from "../api/profile"

const loading = ref(false)
const saving = ref(false)
const message = ref("")

const profile = ref({})

const form = reactive({
  level: "",
  gender: "",
  birthday: "",
  height_cm: "",
  weight_kg: "",
  avatar_url: "",
  intro: "",
  join_time: "",
  expire_date: ""
})

function datetimeToInputValue(value) {
  if (!value) {
    return ""
  }

  return value.replace(" ", "T").slice(0, 16)
}

function inputValueToBackendDatetime(value) {
  if (!value) {
    return null
  }

  return value.replace("T", " ") + ":00"
}

function fillForm(data) {
  profile.value = data

  form.level = data.level ?? ""
  form.gender = data.gender ?? ""
  form.birthday = data.birthday ?? ""
  form.height_cm = data.height_cm ?? ""
  form.weight_kg = data.weight_kg ?? ""
  form.avatar_url = data.avatar_url ?? ""
  form.intro = data.intro ?? ""
  form.join_time = datetimeToInputValue(data.join_time)
  form.expire_date = data.expire_date ?? ""
}

async function loadProfile() {
  try {
    loading.value = true
    message.value = ""

    const res = await getMyProfileApi()

    if (res.code === 200) {
      fillForm(res.data)
    } else {
      message.value = res.message || "获取档案失败"
    }
  } catch (error) {
    if (error.response && error.response.data) {
      message.value = error.response.data.message || "获取档案失败"
    } else {
      message.value = "获取档案失败"
    }
  } finally {
    loading.value = false
  }
}

async function handleSave() {
  try {
    saving.value = true
    message.value = ""

    const payload = {
      level: form.level === "" ? null : Number(form.level),
      gender: form.gender === "" ? null : Number(form.gender),
      birthday: form.birthday || null,
      height_cm: form.height_cm === "" ? null : String(form.height_cm),
      weight_kg: form.weight_kg === "" ? null : String(form.weight_kg),
      avatar_url: form.avatar_url || "",
      intro: form.intro || "",
      join_time: form.join_time
        ? inputValueToBackendDatetime(form.join_time)
        : null,
      expire_date: form.expire_date || null
    }

    const res = await updateMyProfileApi(payload)

    if (res.code === 200) {
      fillForm(res.data)
      message.value = "保存成功"
    } else {
      message.value = res.message || "保存失败"
    }
  } catch (error) {
    if (error.response && error.response.data) {
      message.value = error.response.data.message || "保存失败"
    } else {
      message.value = "保存失败"
    }
  } finally {
    saving.value = false
  }
}

onMounted(() => {
  loadProfile()
})
</script>

### 3.1 关键字段设计

| 字段 | 输入控件 | 提交前处理 |
|------|----------|------------|
| `level` | `number` | 空值置 `null`，否则转 `Number` |
| `gender` | `select`（0 未知 / 1 男 / 2 女） | 空值置 `null`，否则转 `Number` |
| `height_cm` / `weight_kg` | `number`（step 0.01） | 空值置 `null`，否则转 `String` |
| `join_time` | `datetime-local` | 经 `inputValueToBackendDatetime` 转换，空值置 `null` |
| `expire_date` / `birthday` | `date` | 空值置 `null` |
| `avatar_url` / `intro` | 文本 / 多行文本 | 空值置空字符串 |

### 3.2 日期时间转换

后端 `join_time` 以 `"YYYY-MM-DD HH:mm:ss"` 形式返回，前端 `datetime-local` 需要 `"YYYY-MM-DDTHH:mm"` 形式；两者由 `datetimeToInputValue`（读取时）与 `inputValueToBackendDatetime`（保存时）互转。`height_cm`、`weight_kg` 以后端所需的字符串形式提交，`level`、`gender` 以数字形式提交。

**要点**：

- **要点**：读取与保存分别经过 `datetimeToInputValue` 与 `inputValueToBackendDatetime`，保证前后端日期时间格式对齐。
- **要点**：`fillForm` 使用 `??` 为空字段回填初始值，防止受控组件绑定 `undefined` 触发告警。
- **要点**：保存成功后以返回数据再次 `fillForm`，使界面与后端记录保持一致。
- **要点**：`loading` 与 `saving` 分别驱动加载态展示与按钮禁用，避免重复提交。

```javascript
import { createRouter, createWebHistory } from "vue-router"

import { useAuthStore } from "../stores/auth"

import Login from "../views/Login.vue"
import Home from "../views/Home.vue"
import UserList from "../views/UserList.vue"
import StoreList from "../views/StoreList.vue"
import CourseList from "../views/CourseList.vue"
import ExerciseList from "../views/ExerciseList.vue"
import MyFavorites from "../views/MyFavorites.vue"
import Profile from "../views/Profile.vue"
import Forbidden from "../views/Forbidden.vue"

const routes = [
  {
    path: "/login",
    component: Login
  },
  {
    path: "/",
    component: Home,
    meta: {
      requiresAuth: true
    }
  },
  {
    path: "/users",
    component: UserList,
    meta: {
      requiresAuth: true,
      permission: "user:list"
    }
  },
  {
    path: "/store",
    component: StoreList,
    meta: {
      requiresAuth: true
    }
  },
  {
    path: "/course",
    component: CourseList,
    meta: {
      requiresAuth: true
    }
  },
  {
    path: "/exercise",
    component: ExerciseList,
    meta: {
      requiresAuth: true
    }
  },
  {
    path: "/favorites",
    component: MyFavorites,
    meta: {
      requiresAuth: true
    }
  },
  {
    path: "/profile",
    component: Profile,
    meta: {
      requiresAuth: true
    }
  },
  {
    path: "/403",
    component: Forbidden
  }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

router.beforeEach((to, from, next) => {
  const authStore = useAuthStore()

  if (to.meta.requiresAuth && !authStore.isLogin) {
    next("/login")
    return
  }

  if (to.path === "/login" && authStore.isLogin) {
    next("/")
    return
  }

  if (to.meta.permission && !authStore.hasPermission(to.meta.permission)) {
    next("/403")
    return
  }

  next()
})

export default router
```

## 5. 访问控制设计说明

「我的档案」菜单项不添加权限判断，即不写：

```vue
v-if="authStore.hasPermission('profile:me')"
```

原因在于当前设计中：

```text
/profile 是当前登录用户自己的档案
```

该页面仅需登录即可访问，因此路由中声明以下内容即足够：

```javascript
meta: {
  requiresAuth: true
}
```

| 页面 | 访问条件 | 设计依据 |
|------|----------|----------|
| `/profile` | 仅需登录 | 档案归属当前用户本人，无跨用户读写 |
| `/users` | 登录 + `user:list` 权限 | 用户管理涉及他人数据，需权限控制 |

**要点**：

- **要点**：`/profile` 属于「本人数据」类接口，登录态足以界定访问范围，无需权限码。
- **要点**：需要访问他人数据的功能（如用户管理）才叠加 `permission` 判断，二者形成对照。
- **要点**：后端 `GET/PUT /api/profile/me/` 同样依据 token 定位用户，前端与后端的用户隔离一致。

| 路由 | `router/index.js` | 追加 `/profile`，仅设 `requiresAuth` |
| 首页菜单 | `views/Home.vue` | 追加「我的档案」入口 |
| 访问控制 | 路由 `meta` | 本人数据仅登录即可访问 |

## 常见问题与排查

| 现象 | 原因 | 处理方式 |
|------|------|----------|
| 「我的档案」菜单点击后跳转登录页 | 登录态失效或 `access_token` 缺失 | 重新登录；核对 `request.js` 是否附加 `Authorization` |
| 入职/开卡时间无法回填或保存异常 | 后端 `datetime` 与前端 `datetime-local` 格式不一致 | 经 `datetimeToInputValue`（读取）与 `inputValueToBackendDatetime`（保存）互转 |
| 身高、体重保存后类型不符 | 提交值未转换为后端期望的字符串 | 保存前对非空值执行 `String(...)`，空值置 `null` |
| 保存成功但界面未更新 | 未以保存响应回填表单 | 保存成功后调用 `fillForm(res.data)` 刷新展示 |

## 合辑收尾与进阶方向

本阶段完成后，Django 系统阶段开发计划的十八个阶段构成一条贯通的完整链路：

| 层次 | 覆盖阶段 | 交付内容 |
|------|----------|----------|
| 项目与数据底座 | 阶段 1–13 | 项目初始化、数据模型设计、迁移建表、业务测试数据初始化 |
| RBAC 权限体系 | 阶段 4–11 前后段 | 用户、角色、权限三要素，权限拦截与 `login_required` |
| JWT 登录 | 阶段 11 前后段 | 签发与校验 `access_token`，统一响应封装 |
| 业务查询接口 | 阶段 14–16 | 门店、课程、动作三大领域的查询与收藏接口 |
| 前端权限基座 | 阶段 11、14 前后段 | 登录页、`stores/auth`、路由守卫与权限渲染 |
| 前端业务页面 | 阶段 17–18 | 门店、课程、动作、我的收藏、我的档案五个页面 |

系统至此具备「后端数据 + 权限 + 接口」与「前端登录 + 权限路由 + 业务页面」的完整闭环。在此之上，可沿以下方向继续演进：

- **权限缓存与会话优化**：将用户权限集合在服务端缓存，减少每次请求的权限查询开销，并处理 token 续期与登出失效。
- **接口版本化**：为路由引入版本前缀（如 `/api/v1/`），在不破坏既有客户端的前提下迭代接口契约。
- **前端工程化**：引入 UI 组件库与状态管理分层，补齐列表分页、加载骨架、错误边界等交互细节。
- **部署与运维**：配置生产级 Web 服务器与反向代理、静态资源收集、数据库连接与环境变量管理。
- **自动化测试**：为视图与序列化逻辑补充单元测试，为关键接口补充集成测试，保障重构安全。

上述方向均属能力扩展建议，具体实现与指标需依据项目实际条件另行评估。
