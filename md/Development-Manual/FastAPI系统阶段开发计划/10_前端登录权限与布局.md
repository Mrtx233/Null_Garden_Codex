# 10_前端登录权限与布局

## 一、阶段目标

本阶段目标是在前端基础工程已经完成的基础上，实现登录页、Token 保存、用户状态、路由守卫、权限菜单和基础后台布局。

完成本阶段后，前端应具备以下能力：

1. 用户可以通过 `/login` 登录。
2. 登录成功后保存后端返回的 Token。
3. 刷新页面后可以根据 Token 恢复当前用户信息。
4. 未登录访问后台页面会跳转到登录页。
5. 已登录访问登录页会跳转回首页。
6. 布局侧边栏可以根据后端菜单数据展示菜单。
7. 没有真实页面的菜单先进入占位页面，后续阶段再替换为业务页面。
8. 退出登录后清空本地 Token 和用户状态。

## 五、步骤 1：创建认证 API 封装

```ts
import { request } from './http'

export interface LoginPayload {
  username: string
  password: string
}

export interface UserInfo {
  user_id: number
  role_id: number
  username: string
  real_name: string | null
  phone: string | null
  status: number | null
}

export interface LoginResult {
  access_token: string
  token_type: string
  user: UserInfo
  permissions: string[]
}

export interface MenuItem {
  permission_code: string
  permission_name: string
  menu_path: string
}

export function loginApi(data: LoginPayload) {
  return request<LoginResult>({
    url: '/auth/login',
    method: 'post',
    data,
  })
}

export function getMeApi() {
  return request<UserInfo>({
    url: '/auth/me',
    method: 'get',
  })
}

export function getPermissionsApi() {
  return request<string[]>({
    url: '/auth/permissions',
    method: 'get',
  })
}

export function getMenusApi() {
  return request<MenuItem[]>({
    url: '/auth/menus',
    method: 'get',
  })
}
```

### 注意事项

1. `loginApi` 对接后端 `/api/auth/login`。
2. `getMenusApi` 返回后端 `sys_permission.menu_path` 对应的菜单。
3. 前端菜单路径需要和后端种子权限中的 `menu_path` 保持一致。

### 完整代码

```ts
import { computed, ref } from 'vue'
import { defineStore } from 'pinia'

import {
  getMeApi,
  getMenusApi,
  getPermissionsApi,
  loginApi,
  type LoginPayload,
  type MenuItem,
  type UserInfo,
} from '../api/auth'

const TOKEN_KEY = 'joyfit_token'

export const useAuthStore = defineStore('auth', () => {
  const token = ref(localStorage.getItem(TOKEN_KEY) || '')
  const user = ref<UserInfo | null>(null)
  const permissions = ref<string[]>([])
  const menus = ref<MenuItem[]>([])

  const isLoggedIn = computed(() => Boolean(token.value))
  const displayName = computed(() => user.value?.real_name || user.value?.username || '管理员')

  function setToken(value: string) {
    token.value = value
    localStorage.setItem(TOKEN_KEY, value)
  }

  function clearAuth() {
    token.value = ''
    user.value = null
    permissions.value = []
    menus.value = []
    localStorage.removeItem(TOKEN_KEY)
  }

  async function login(payload: LoginPayload) {
    const result = await loginApi(payload)

    setToken(result.access_token)
    user.value = result.user
    permissions.value = result.permissions
    menus.value = await getMenusApi()

    return result
  }

  async function loadProfile() {
    if (!token.value) {
      return
    }

    try {
      const [currentUser, permissionList, menuList] = await Promise.all([
        getMeApi(),
        getPermissionsApi(),
        getMenusApi(),
      ])

      user.value = currentUser
      permissions.value = permissionList
      menus.value = menuList
    } catch (error) {
      clearAuth()
      throw error
    }
  }

  function hasPermission(permissionCode: string) {
    return permissions.value.includes(permissionCode)
  }

  function logout() {
    clearAuth()
  }

  return {
    token,
    user,
    permissions,
    menus,
    isLoggedIn,
    displayName,
    login,
    loadProfile,
    hasPermission,
    logout,
    clearAuth,
  }
})
```

### 注意事项

1. Token 存储在 `localStorage.joyfit_token`。
2. 刷新页面后，Store 会先从 `localStorage` 恢复 Token。
3. 路由守卫会调用 `loadProfile` 补齐用户、权限、菜单。

### 相对路径

```text
frontend/src/api/http.ts
```

### 完整代码

```ts
import axios, {
  type AxiosError,
  type AxiosInstance,
  type AxiosRequestConfig,
  type InternalAxiosRequestConfig,
} from 'axios'
import { ElMessage } from 'element-plus'

import type { ApiResponse } from './types'

const TOKEN_KEY = 'joyfit_token'

const http: AxiosInstance = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  timeout: 10000,
})

http.interceptors.request.use((config: InternalAxiosRequestConfig) => {
  const token = localStorage.getItem(TOKEN_KEY)

  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }

  return config
})

http.interceptors.response.use(
  (response) => {
    const body = response.data as ApiResponse

    if (body && typeof body.code === 'number' && body.code !== 200) {
      ElMessage.error(body.message || '请求失败')
      return Promise.reject(body)
    }

    return response
  },
  (error: AxiosError<ApiResponse>) => {
    const status = error.response?.status
    const message = error.response?.data?.message || error.message || '网络请求失败'

    if (status === 401) {
      localStorage.removeItem(TOKEN_KEY)

      if (window.location.pathname !== '/login') {
        const redirect = `${window.location.pathname}${window.location.search}`
        window.location.href = `/login?redirect=${encodeURIComponent(redirect)}`
      }
    } else {
      ElMessage.error(message)
    }

    return Promise.reject(error)
  },
)

export async function request<T = unknown>(config: AxiosRequestConfig): Promise<T> {
  const response = await http.request<ApiResponse<T>>(config)
  return response.data.data
}

export default http
```

### 注意事项

1. 401 会清除 Token 并跳转登录页。
2. 业务错误 `code !== 200` 会统一提示。
3. 这里没有直接导入 Pinia Store，避免请求层和状态层循环依赖。

```ts
          requiresAuth: true,
          permission: 'permission:list',

    path: '/:pathMatch(.*)*',
    name: 'not-found',
    component: () => import('../views/NotFoundView.vue'),
    meta: {
      title: '页面不存在',
    },
  },
]

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes,
})

router.beforeEach(async (to) => {
  const authStore = useAuthStore()

  if (to.meta.guestOnly && authStore.isLoggedIn) {
    return { name: 'home' }
  }

  if (to.meta.requiresAuth && !authStore.isLoggedIn) {
    return {
      name: 'login',
      query: {
        redirect: to.fullPath,
      },
    }
  }

  if (to.meta.requiresAuth && authStore.isLoggedIn && !authStore.user) {
    try {
      await authStore.loadProfile()
    } catch (error) {
      return {
        name: 'login',
        query: {
          redirect: to.fullPath,
        },
      }
    }
  }

  if (to.meta.permission && !authStore.hasPermission(to.meta.permission)) {
    ElMessage.error('没有访问权限')
    return { name: 'home' }
  }

  return true
})

router.afterEach((to) => {
  const title = to.meta.title ? `${String(to.meta.title)} - JoyFit` : 'JoyFit'
  document.title = title
})

export default router
```

### 注意事项

1. `/login` 不需要登录。
2. `/` 和后台菜单都需要登录。
3. 菜单路径和后端 `menu_path` 保持一致，例如 `/users`、`/courses`、`/content/events`。
4. 真实页面还没开发时，先统一进入 `PlaceholderView.vue`。

```vue
import { ElMessage, type FormInstance, type FormRules } from 'element-plus'
```

## 十五、常见问题

### 1. 登录返回 401

原因：

用户名或密码不正确，或者后端管理员账号没有初始化成功。

修复：

1. 确认后端启动时 `AUTO_SEED_DATA=true`。
2. 使用默认账号 `admin / 123456`。
3. 如果修改过管理员密码，使用你自己的密码登录。

### 2. 登录成功后菜单为空

原因：

当前角色没有带 `menu_path` 的权限，或者 `/api/auth/menus` 返回空数组。

修复：

1. 使用管理员账号登录。
2. 检查 `sys_permission.menu_path` 是否有值。
3. 检查 `sys_role_permission` 是否绑定了对应权限。

### 3. 刷新页面后又回到登录页

原因：

Token 无效、过期，或者后端 `/api/auth/me` 返回 401。

修复：

重新登录，并确认后端服务没有重置 `JWT_SECRET_KEY`。

### 4. 点击菜单进入 404

原因：

后端 `menu_path` 和前端路由路径不一致。

修复：

1. 检查后端 `DEFAULT_PERMISSIONS` 中的 `menu_path`。
2. 检查前端 `router/index.ts` 中是否配置了同路径路由。

### 5. `npm run build` 提示找不到 `.vue`

原因：

缺少 `src/vite-env.d.ts`。

修复：

按第九阶段的问题记录补齐 `frontend/src/vite-env.d.ts`。
