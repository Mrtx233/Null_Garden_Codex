# 00_开发步骤总览

## 一、总览说明

本文件用于说明 FastAPI_Vue3_JoyFit 系统从零开发时的整体步骤。

开发顺序必须遵循：

```text
先完成后端构建 -> 再完成前端构建 -> 最后进行前后端联调与部署
```

原因：

1. 数据库表结构已经确定，后端应先根据 DDL 完成模型、接口、认证、权限和业务逻辑。
2. 前端页面依赖后端接口返回的数据结构，后端接口稳定后再开发前端效率更高。
3. 先完成后端可以提前生成 Swagger 文档，前端可以直接按接口文档对接。

## 二、项目目录规划

最终项目目录建议如下：

```text
FastAPI_Vue3_JoyFit/
  backend/        # FastAPI 后端项目
  frontend/       # Vue3 前端项目
  sql/            # 数据库 SQL 文件
  md/             # 阶段开发说明文档
```

当前阶段只先创建开发说明文档，不需要立刻创建后端和前端项目代码。

## 四、第一部分：数据库准备

### 步骤 1：确认 SQL 文件

要做什么：

检查 `sql/ddl.sql` 是否存在，并确认里面包含数据库创建语句和全部业务表结构。

为什么做：

后端 ORM 模型、接口字段、业务关系都要根据 DDL 来设计。

完成产出：

```text
sql/ddl.sql
```

检查重点：

- 数据库名是否为 `FastAPI_Vue3_JoyFit`
- 字符集是否为 `utf8mb4`
- 所有表是否都使用 InnoDB
- 外键依赖顺序是否正确

### 步骤 2：导入 MySQL 数据库

要做什么：

将 `ddl.sql` 导入 MySQL。

为什么做：

只有数据库表真实存在，后端才能测试数据库连接和接口查询。

完成产出：

```text
MySQL 数据库：FastAPI_Vue3_JoyFit
```

验收方式：

```sql
SHOW DATABASES;
USE FastAPI_Vue3_JoyFit;
SHOW TABLES;
```

### 步骤 3：整理数据表模块归属

要做什么：

把表按业务模块分组。

为什么做：

后端开发时需要按模块创建模型、Schema、Service、Router。

表分组：

| 模块 | 数据表 |
| --- | --- |
| 系统权限 | `sys_permission`、`sys_role`、`sys_role_permission` |
| 用户体系 | `sys_user`、`sys_user_profile` |
| 首页内容 | `t_slogan_info` |
| 活动赛事 | `t_activity_event` |
| 门店体系 | `t_store_province`、`t_store`、`y_user_store` |
| 课程体系 | `t_course_category`、`t_course`、`y_user_course_favorite` |
| 动作库 | `t_action_category`、`t_action`、`y_user_action_favorite` |

## 五、第二部分：后端基础工程构建

### 步骤 4：创建 FastAPI 后端项目目录

要做什么：

在 `backend` 中创建 FastAPI 后端工程基础目录。

为什么做：

让后端代码从一开始就按照分层结构组织，避免后续接口越来越多时混乱。

建议目录：

```text
backend/
  app/
    api/
    core/
    db/
    models/
    schemas/
    services/
    utils/
    main.py
  tests/
  requirements.txt
  .env.example
```

完成产出：

- 后端入口文件 `app/main.py`
- 配置目录 `app/core`
- 数据库目录 `app/db`
- 模型目录 `app/models`
- 接口目录 `app/api`

### 步骤 5：创建 Python 虚拟环境

要做什么：

为后端项目创建独立 Python 环境。

为什么做：

隔离项目依赖，避免不同项目依赖版本互相影响。

完成产出：

```text
backend/.venv/
```

### 步骤 6：安装后端基础依赖

要做什么：

安装 FastAPI、数据库、配置、认证相关依赖。

为什么做：

这些依赖是后端启动、连接数据库、处理请求和后续实现登录权限的基础。

建议依赖：

| 依赖 | 作用 |
| --- | --- |
| `fastapi` | 后端 Web 框架 |
| `uvicorn` | FastAPI 运行服务器 |
| `sqlalchemy` | ORM 数据库操作 |
| `pymysql` | MySQL 驱动 |
| `pydantic-settings` | 读取环境变量配置 |
| `alembic` | 数据库迁移管理 |
| `python-jose` | JWT Token |
| `passlib` | 密码加密 |
| `bcrypt` | 密码哈希 |

完成产出：

```text
backend/requirements.txt
```

### 步骤 7：编写环境变量配置

要做什么：

创建 `.env.example`，声明数据库、JWT、CORS 等配置项。

为什么做：

配置和代码分离，方便开发环境、测试环境、生产环境切换。

完成产出：

```text
backend/.env.example
```

应包含：

- MySQL 地址
- MySQL 端口
- MySQL 用户名
- MySQL 密码
- 数据库名
- JWT 密钥
- Token 过期时间
- CORS 允许来源

### 步骤 8：编写后端配置模块

要做什么：

在 `app/core/config.py` 中读取 `.env` 配置。

为什么做：

后端所有配置统一从一个地方读取，数据库连接、JWT、CORS 都可以复用。

完成产出：

```text
backend/app/core/config.py
```

主要功能：

- 读取项目名称
- 读取数据库配置
- 生成数据库连接字符串
- 读取 JWT 配置
- 读取 CORS 配置

### 步骤 9：编写数据库连接模块

要做什么：

在 `app/db/session.py` 中创建 SQLAlchemy Engine 和 Session。

为什么做：

后续所有接口都需要通过数据库 Session 查询或写入数据。

完成产出：

```text
backend/app/db/session.py
```

主要功能：

- 创建数据库 Engine
- 创建 SessionLocal
- 提供 `get_db()` 依赖
- 请求结束后关闭 Session

### 步骤 10：编写后端主入口

要做什么：

编写 `app/main.py`，创建 FastAPI 实例。

为什么做：

这是后端服务的启动入口，所有路由、中间件、异常处理都从这里注册。

完成产出：

```text
backend/app/main.py
```

主要功能：

- 创建 FastAPI 应用
- 配置 CORS
- 注册 API 路由
- 注册异常处理器
- 开启 Swagger 文档

### 步骤 11：编写健康检查接口

要做什么：

创建 `/api/health` 接口。

为什么做：

用于验证后端服务是否正常启动，也方便前端测试接口联通。

完成产出：

```text
GET /api/health
```

返回示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "status": "ok"
  }
}
```

### 步骤 12：验证后端基础服务

要做什么：

启动 FastAPI 服务并访问接口文档。

为什么做：

确认后端工程已经可以运行，基础配置没有问题。

验收地址：

```text
http://127.0.0.1:8000/docs
http://127.0.0.1:8000/api/health
```

完成标准：

- `/docs` 可以打开
- `/api/health` 可以返回成功
- 后端控制台没有启动报错

## 六、第三部分：后端 ORM 模型构建

### 步骤 13：创建 SQLAlchemy Base

要做什么：

在 `app/db/base.py` 中创建 ORM 基类。

为什么做：

所有 ORM 模型都要继承 Base，后续 Alembic 迁移也依赖 Base metadata。

完成产出：

```text
backend/app/db/base.py
```

### 步骤 14：按表创建 ORM 模型

要做什么：

根据 DDL 为每张表创建 SQLAlchemy 模型。

为什么做：

接口不能直接写 SQL，应通过 ORM 模型进行数据操作。

建议模型文件：

```text
backend/app/models/
  system.py      # 角色、权限、角色权限
  user.py        # 用户、用户档案
  store.py       # 省份、门店、用户门店
  course.py      # 课程分类、课程、课程收藏
  action.py      # 动作分类、动作、动作收藏
  content.py     # Slogan、活动
```

完成产出：

- `SysPermission`
- `SysRole`
- `SysRolePermission`
- `SysUser`
- `SysUserProfile`
- `StoreProvince`
- `Store`
- `UserStore`
- `CourseCategory`
- `Course`
- `UserCourseFavorite`
- `ActionCategory`
- `Action`
- `UserActionFavorite`
- `SloganInfo`
- `ActivityEvent`

### 步骤 15：建立 ORM 关系

要做什么：

给有关联的模型补充 relationship。

为什么做：

方便后续查询用户角色、角色权限、课程分类、门店省份等关联数据。

重点关系：

- 用户 -> 角色
- 用户 -> 用户档案
- 角色 -> 权限
- 门店 -> 省份
- 用户 -> 门店
- 课程 -> 分类
- 动作 -> 分类
- 用户 -> 课程收藏
- 用户 -> 动作收藏

### 步骤 16：验证 ORM 与数据库一致

要做什么：

通过简单查询验证 ORM 模型字段和数据库字段是否一致。

为什么做：

避免后续接口开发时出现字段名错误、类型错误、外键关系错误。

完成标准：

- 所有模型可以正常导入
- 数据库连接正常
- 简单查询不报错

建议 Store：

- `auth`
- `permission`
- `app`

## 十二、第九部分：前端登录权限开发

### 步骤 40：开发登录页

要做什么：

实现用户名密码登录表单。

为什么做：

用户需要登录后才能进入后台。

对接接口：

```text
POST /api/auth/login
```

### 步骤 41：开发路由守卫

要做什么：

拦截未登录访问后台页面的请求。

为什么做：

防止未登录用户直接进入后台页面。

规则：

- 未登录访问后台，跳转 `/login`
- 已登录访问 `/login`，跳转 `/dashboard`
- 无权限访问页面，跳转 403 或隐藏入口

### 步骤 42：开发动态菜单

要做什么：

根据后端返回的菜单权限生成后台菜单。

为什么做：

不同角色应该看到不同菜单。

对接接口：

```text
GET /api/auth/menus
```

要做什么：

为什么做：

检查项：

- 开发环境 API 地址
- 生产环境 API 地址
- Vite 代理配置

### 步骤 53：联调登录权限

验收标准：

- 登录成功

- Token 失效自动退出
- 菜单按角色展示
- 无权限按钮隐藏

要做什么：

逐个页面测试列表、新增、编辑、删除。

- 用户
- 角色
- 权限
- 门店
- 课程
- 动作
- Slogan
- 活动

要做什么：

测试首页、详情页、收藏功能。

为什么做：

测试重点：

- 首页数据展示
- 课程详情
- 动作详情
- 活动详情
- 收藏和取消收藏

要做什么：

执行前端打包。

完成产出：

```text
frontend/dist/
```

### 步骤 58：Nginx 反向代理

要做什么：

配置 Nginx 托管前端静态文件，并代理后端 API。

为什么做：

线上访问时，用户访问同一个域名即可打开前端并请求后端接口。

主要配置：

- `/` 指向前端 `dist`
- `/api` 代理到 FastAPI
- history 路由回退到 `index.html`
