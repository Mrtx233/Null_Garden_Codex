# 11_前端后台管理页面

## 一、阶段目标

本阶段目标是在登录、Token、权限菜单、后台基础布局已经完成的基础上，把上一阶段的 `PlaceholderView.vue` 占位页替换成真实后台管理页面。

完成本阶段后，前端应具备以下能力：

1. 用户管理页面可以查询、新增、编辑、启停用户。
2. 门店管理页面可以维护省份和门店。
3. 课程管理页面可以维护课程分类和课程。
4. 动作库页面可以维护动作分类和动作条目。
5. 活动管理页面可以维护赛事活动。
6. Slogan 管理页面可以维护首页标语。
7. 角色管理页面可以维护角色基础信息。
8. 权限管理页面可以查看后端初始化的权限列表。
9. 路由不再进入占位页，而是进入对应业务管理页。

说明：当前后端已经提供 `PUT /api/system/roles/{role_id}/permissions`，但没有提供“查询某个角色当前权限 ID 列表”的接口，所以本阶段先不做角色权限勾选分配页面，避免前端无法回显当前权限导致误覆盖。后续如果补充 `GET /api/system/roles/{role_id}/permissions`，再单独增加角色权限分配弹窗。

```vue
<script setup lang="ts">
import { onMounted, reactive, ref } from 'vue'
import { ElMessage, type FormInstance } from 'element-plus'
import { Plus, Refresh, Search } from '@element-plus/icons-vue'

import { listRolesApi, type Role } from '../../api/system'
import {
  createUserApi,
  listUsersApi,
  updateUserApi,
  updateUserStatusApi,
  type User,
  type UserForm,
} from '../../api/user'

const loading = ref(false)
const users = ref<User[]>([])
const roles = ref<Role[]>([])
const total = ref(0)
const formRef = ref<FormInstance>()
const dialogVisible = ref(false)
const editingId = ref<number | null>(null)

const query = reactive({
  page: 1,
  page_size: 10,
  keyword: '',
  status: undefined as number | undefined,
  role_id: undefined as number | undefined,
})

const form = reactive<UserForm>({
  role_id: 0,
  username: '',
  password: '',
  real_name: '',
  phone: '',
  status: 1,
})

function roleName(roleId: number) {
  return roles.value.find((item) => item.id === roleId)?.role_name || `角色 ${roleId}`
}

function resetForm() {
  form.role_id = roles.value[0]?.id || 0
  form.username = ''
  form.password = ''
  form.real_name = ''
  form.phone = ''
  form.status = 1
}

async function fetchRoles() {
  roles.value = await listRolesApi()
  if (!form.role_id) {
    form.role_id = roles.value[0]?.id || 0
  }
}

async function fetchUsers() {
  loading.value = true
  try {
    const result = await listUsersApi({
      page: query.page,
      page_size: query.page_size,
      keyword: query.keyword || undefined,
      status: query.status,
      role_id: query.role_id,
    })

    users.value = result.items
    total.value = result.total
  } finally {
    loading.value = false
  }
}

function search() {
  query.page = 1
  fetchUsers()
}

function resetSearch() {
  query.page = 1
  query.keyword = ''
  query.status = undefined
  query.role_id = undefined
  fetchUsers()
}

function openCreate() {
  editingId.value = null
  resetForm()
  dialogVisible.value = true
}

function openEdit(row: User) {
  editingId.value = row.user_id
  form.role_id = row.role_id
  form.username = row.username
  form.password = ''
  form.real_name = row.real_name || ''
  form.phone = row.phone || ''
  form.status = row.status ?? 1
  dialogVisible.value = true
}

async function submitForm() {
  await formRef.value?.validate()

  if (!form.role_id) {
    ElMessage.warning('请选择角色')
    return
  }

  if (!editingId.value && !form.password) {
    ElMessage.warning('新增用户必须填写密码')
    return
  }

  const payload: Partial<UserForm> = {
    role_id: form.role_id,
    username: form.username,
    real_name: form.real_name || null,
    phone: form.phone || null,
    status: form.status,

    }
  }

  if (to.meta.permission && !authStore.hasPermission(to.meta.permission)) {
    ElMessage.error('没有访问权限')
    return { name: 'home' }
  }

  return true
})

router.afterEach((to) => {
  const title = to.meta.title ? `${String(to.meta.title)} - JoyFit` : 'JoyFit'
  document.title = title
})

export default router
```

## 二十二、常见问题

### 1. 页面提示没有访问权限

先确认当前登录账号拥有对应权限，例如：

| 页面 | 需要权限 |
| --- | --- |
| 用户管理 | `user:list` |
| 门店管理 | `store:list` |
| 课程管理 | `course:list` |
| 动作库 | `action:list` |
| 活动管理 | `event:list` |
| Slogan 管理 | `slogan:list` |
| 角色管理 | `role:list` |
| 权限管理 | `permission:list` |

如果使用的是初始化管理员账号，正常应该拥有全部权限。若没有，检查后端 `seed.py` 是否已经给 `admin` 角色绑定全部权限。

### 2. 删除分类失败

如果某个课程分类、动作分类、省份下面已经有关联数据，数据库外键会阻止删除。

处理方式：

1. 先删除或修改依赖该分类、省份的数据。
2. 再删除分类或省份。

### 3. 角色权限分配为什么本阶段没做

当前后端有更新角色权限的接口：

```text
PUT /api/system/roles/{role_id}/permissions
```

但没有查询当前角色已有权限的接口。

如果前端直接做多选框，打开弹窗时无法知道哪些权限已经被选中。用户一保存，就可能把原权限覆盖掉。因此本阶段先只做角色基础信息维护和权限列表查看。

后续建议补充：

```text
GET /api/system/roles/{role_id}/permissions
```

返回：

```json
{
  "code": 200,
  "message": "success",
  "data": [1, 2, 3]
}
```

然后再接入角色权限分配弹窗。
