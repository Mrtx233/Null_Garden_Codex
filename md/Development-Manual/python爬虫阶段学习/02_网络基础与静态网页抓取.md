## 1. HTTP/HTTPS 网络协议基础

### 1.1 请求与响应模型

HTTP（HyperText Transfer Protocol，超文本传输协议）是客户端与服务器之间的请求-响应式协议，一次交互的形式为：

```text
客户端                            服务器
   │                               │
   ├──── 请求 (Request) ─────────→ │
   │                               ├──── 处理中
   │ ←──────── 响应 (Response) ────┤
   │                               │
```

一次 HTTP 交互由客户端发起请求、服务器返回响应两部分构成。HTTPS（HTTP Secure）是在 HTTP 之上增加 TLS 加密层后的协议形态，链路中的传输内容被加密。

以下代码使用 Python 标准库展示该流程的四个阶段：

```python
# 请求-响应流程的底层实现
import http.client

# 1. 建立连接
conn = http.client.HTTPSConnection("www.example.com")

# 2. 发送请求
conn.request("GET", "/")

# 3. 获取响应
response = conn.getresponse()

# 4. 读取内容
print(f"状态码: {response.status}")        # 200
print(f"响应头: {response.getheaders()}")  # 头部信息集合
data = response.read()                     # 页面的 HTML 内容
conn.close()
```

实际爬虫中不使用 `http.client`，因其层级过低、连接与细节需手动处理；通常使用 `requests` 库。但该流程是理解所有上层请求库的基础。

### 1.2 常见请求方法

请求方法用于声明本次请求的目的。爬虫中最常用的是 GET 与 POST，其余方法作了解要求。

| 方法 | 语义 | 是否改变服务器状态 | 爬虫中的典型场景 |
|------|------|--------------------|------------------|
| GET | 从服务器获取资源 | 否（只读） | 页面浏览、资源检索、接口数据获取 |
| POST | 向服务器提交数据 | 是（写入） | 登录、表单提交、JSON 接口调用 |
| PUT | 整体更新资源（覆盖） | 是 | 覆盖式更新，爬虫中较少使用 |
| PATCH | 部分更新资源 | 是 | 局部字段更新，爬虫中较少使用 |
| DELETE | 删除资源 | 是 | 删除操作，爬虫中较少使用 |

```python
# 最常用：GET 获取资源，POST 提交数据
# GET 请求不改变服务器状态，参数通常出现在 URL 的查询串中
# POST 请求将数据写入请求体，用于登录与表单提交

# 其余方法（PUT / DELETE / PATCH）在爬虫中较少直接使用
```

GET 与 POST 的差异不仅是方法名，还体现在参数位置（查询串与请求体）、幂等性以及服务器端的校验方式上；实际抓取时需与目标接口的实现保持一致。

### 1.3 Request Headers（请求头）

请求头是请求中用于声明客户端身份、可接受的响应类型与会话状态的元信息。服务器依据请求头判断请求来源是否合法。

| 字段 | 含义 | 在爬虫中的作用 |
|------|------|----------------|
| User-Agent | 客户端标识（浏览器与系统信息） | 反爬虫最基础的检查项；未设置时常被直接拒绝 |
| Referer | 来源页面地址 | 防盗链校验与来源统计 |
| Cookie | 会话与身份标识 | 携带登录状态，服务器据此识别用户身份 |
| Accept | 客户端可接受的响应类型 | 可要求返回 JSON 而非 HTML |
| Accept-Language | 期望的自然语言 | 决定返回中文或英文内容 |
| Authorization | 身份认证令牌（如 Bearer 形式） | API 接口调用常用 |

```python
headers = {
    # 核心字段
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",  # 客户端标识，反爬虫基础检查项
    "Referer": "https://www.google.com/",           # 来源页面地址，用于防盗链与来源统计
    "Cookie": "session_id=abc123; user=zhangsan",   # 会话与身份信息，服务器据此识别用户

    # 其他常用字段
    "Accept": "text/html,application/json,*/*",     # 可接受的响应类型，可要求返回 JSON
    "Accept-Language": "zh-CN,zh;q=0.9,en;q=0.8",   # 期望的自然语言，决定返回中英文内容
    "Authorization": "Bearer token123",             # 身份认证令牌，API 调用常用
}

# 未设置 User-Agent 的请求，多数网站直接返回 403 拒绝访问
# 配置为常见浏览器形态后，服务器将该请求按普通用户处理
```

### 1.4 常见状态码

状态码表示服务器对请求的处理结果，是爬虫决定后续行为的直接依据。

| 分类 | 状态码 | 含义 | 爬虫中的典型处理 |
|------|--------|------|------------------|
| 2xx 成功 | 200 | OK，请求成功，响应中包含数据 | 解析响应数据 |
| 2xx 成功 | 201 | Created，资源创建成功（POST 请求后常见） | 确认写入结果 |
| 2xx 成功 | 204 | No Content，请求成功但无内容返回（DELETE 后常见） | 视为操作成功 |
| 3xx 重定向 | 301 | Moved Permanently，永久重定向（地址已变更） | 跟随重定向并更新目标 URL |
| 3xx 重定向 | 302 | Found，临时重定向 | 跟随重定向 |
| 3xx 重定向 | 304 | Not Modified，内容未变化 | 使用本地缓存（与浏览器缓存机制相关） |
| 4xx 客户端错误 | 400 | Bad Request，请求格式错误 | 检查请求参数与编码 |
| 4xx 客户端错误 | 401 | Unauthorized，未登录或未认证 | 补充登录或认证信息 |
| 4xx 客户端错误 | 403 | Forbidden，服务器拒绝访问（反爬虫最常见） | 更换代理或补充请求头 |
| 4xx 客户端错误 | 404 | Not Found，页面不存在 | 校验 URL 构造 |
| 4xx 客户端错误 | 429 | Too Many Requests，请求过于频繁被限流 | 降低频率，等待后重试 |
| 5xx 服务器错误 | 500 | Internal Server Error，服务器内部错误 | 等待后重试 |
| 5xx 服务器错误 | 502 | Bad Gateway，网关错误（上游服务异常） | 等待后重试 |
| 5xx 服务器错误 | 503 | Service Unavailable，服务器暂时不可用 | 等待后重试 |

状态码集合在代码中常以字典形式维护，便于查询与统一输出：

```python
status_codes = {
    # 2xx 成功
    200: "OK - 请求成功，响应中有数据",
    201: "Created - 创建成功（POST 请求后常见）",
    204: "No Content - 请求成功但无内容返回（DELETE 后常见）",

    # 3xx 重定向
    301: "Moved Permanently - 永久重定向（地址已变更）",
    302: "Found - 临时重定向（暂时跳转至其他地址）",
    304: "Not Modified - 内容未变化，使用缓存（与浏览器缓存机制相关）",

    # 4xx 客户端错误
    400: "Bad Request - 请求格式错误",
    401: "Unauthorized - 未登录或未认证",
    403: "Forbidden - 服务器拒绝（反爬虫最常见）",
    404: "Not Found - 页面不存在",
    429: "Too Many Requests - 请求过于频繁，被限流",

    # 5xx 服务器错误
    500: "Internal Server Error - 服务器内部错误",
    502: "Bad Gateway - 网关错误（服务器上游异常）",
    503: "Service Unavailable - 服务器暂时不可用",
}
```

爬虫中依据状态码分派处理逻辑：

```python
# 依据状态码决定爬虫行为
def handle_response(status_code):
    if status_code == 200:
        return "解析数据"
    elif status_code == 301 or status_code == 302:
        return "跟随重定向"
    elif status_code == 403:
        return "请求被拒绝，更换代理或补充请求头"
    elif status_code == 429:
        return "频率过高，降低请求速度后重试"
    elif status_code >= 500:
        return "服务器异常，稍后重试"
    else:
        return "其他情况"
```

**本章要点**：

- **要点**：HTTP 交互遵循请求-响应模型，爬虫的本质是构造请求并解析响应。
- **要点**：GET 用于获取资源、POST 用于提交数据，二者构成爬虫的主要请求方式。
- **要点**：User-Agent 是反爬虫识别的第一道检查项，必须随请求设置。
- **要点**：状态码决定后续处理分支——200 解析、403 更换代理、429 降低频率、5xx 等待重试。

### 2.2 GET 请求

```python
import requests

# 基本 GET 请求
response = requests.get("https://api.example.com/users")
print(response.text)          # 响应内容（字符串）
print(response.content)       # 响应内容（字节，下载图片等二进制文件使用）
print(response.status_code)   # 状态码 200
print(response.headers)       # 响应头（字典）
print(response.url)           # 最终请求的 URL（可能已被重定向）

# 带参数的 GET
# 方式 1：直接拼接在 URL 中
response = requests.get("https://api.example.com/search?q=手机&page=1")

# 方式 2：使用 params 参数（推荐，自动处理编码）
params = {
    "q": "手机",
    "page": 1,
    "sort": "price"
}
response = requests.get("https://api.example.com/search", params=params)
# 实际请求的 URL：https://api.example.com/search?q=%E6%89%8B%E6%9C%BA&page=1&sort=price

# 带请求头的 GET
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
    "Accept": "text/html,application/json,*/*",
}
response = requests.get("https://example.com", headers=headers)

# 设置超时（必须设置，否则请求可能长时间阻塞）
response = requests.get("https://example.com", timeout=10)
# timeout=10 表示连接与读取的总时长不超过 10 秒
# 也可分别设置：(连接超时, 读取超时)
response = requests.get("https://example.com", timeout=(5, 10))

# 处理编码
response = requests.get("https://example.com")
response.encoding = "utf-8"   # 手动指定编码（自动检测可能不准确）
print(response.text)          # 按指定编码解码后的文本
```

### 2.3 POST 请求

```python
import requests

# 提交表单数据（最常见）
data = {
    "username": "zhangsan",
    "password": "123456"
}
response = requests.post("https://example.com/login", data=data)
# data 参数会自动编码为 application/x-www-form-urlencoded

# 提交 JSON 数据（API 调用最常用）
json_data = {
    "username": "zhangsan",
    "password": "123456"
}
response = requests.post("https://api.example.com/login", json=json_data)
# json 参数会自动序列化并设置 Content-Type: application/json

# 上传文件
files = {
    "file": open("report.txt", "rb")
}
response = requests.post("https://example.com/upload", files=files)

# 使用 with 语句确保文件关闭
with open("report.txt", "rb") as f:
    response = requests.post("https://example.com/upload", files={"file": f})
```

| 参数 | 编码形式 | Content-Type | 适用场景 |
|------|----------|--------------|----------|
| `data=dict` | 表单键值对 | application/x-www-form-urlencoded | 传统表单提交、登录接口 |
| `json=dict` | JSON 字符串 | application/json | RESTful API 调用 |
| `files=dict` | multipart/form-data | multipart/form-data | 文件上传 |

`data` 与 `json` 的选择错误通常直接导致 400 或 415 响应。

### 2.4 requests.Session() — 会话维持

```python
import requests

# 不使用 Session 的问题：每次请求相互独立，不携带 Cookie
requests.post("https://example.com/login", data={"user": "admin", "pass": "123"})
# 上一条登录请求已成功
requests.get("https://example.com/profile")  # 该请求仍需重新登录

# 使用 Session 解决
session = requests.Session()
# Session 对象自动保存响应中的 Cookie，并在后续请求中自动携带

# 登录
login_data = {"username": "admin", "password": "123456"}
session.post("https://example.com/login", data=login_data)
# 此处服务器返回的 Set-Cookie 被 session 记录

# 访问需要登录的页面
response = session.get("https://example.com/profile")
# 自动携带此前的 Cookie，服务器可识别用户身份

# Session 的其他作用
session.headers.update({"User-Agent": "Mozilla/5.0"})
# 设置一次，该 session 的所有请求均生效
```

```python
# 爬虫实战：模拟登录获取数据
def login_and_get_data(username, password):
    """模拟登录并获取登录后的数据"""
    session = requests.Session()

    # 1. 先访问登录页面，获取必要的 Cookie 和 token
    login_page = session.get("https://example.com/login")
    # 解析出可能需要的 csrf_token（部分站点要求）

    # 2. 提交登录
    login_data = {
        "username": username,
        "password": password,
        # "csrf_token": csrf_token  # 部分站点需要该字段
    }
    resp = session.post("https://example.com/login", data=login_data)

    if resp.status_code == 200:
        # 3. 使用同一个 session 访问需要登录的页面
        profile = session.get("https://example.com/my/profile")
        return profile.text
    else:
        print("登录失败")
        return None
```

登录成功与否的判断不能只依赖状态码：部分站点在凭证错误时仍返回 200，需进一步检查响应中的提示字样或 Cookie 中的特定字段。

### 2.5 代理设置

代理（Proxy）用于将请求经由中间服务器转发，从而更换出口 IP，是应对 IP 封禁与频率限制的主要手段。

```python
import requests

# 设置代理
proxies = {
    "http": "http://127.0.0.1:7890",    # HTTP 代理
    "https": "http://127.0.0.1:7890",   # HTTPS 代理（通常与 HTTP 使用同一地址）
}
response = requests.get("https://example.com", proxies=proxies)

# 带认证的代理
proxies = {
    "http": "http://user:password@127.0.0.1:7890",
    "https": "http://user:password@127.0.0.1:7890",
}
```

```python
import requests
import random

# 爬虫实战：轮换代理
proxy_list = [
    "http://proxy1.com:8080",
    "http://proxy2.com:8080",
    "http://proxy3.com:8080",
]

def fetch_with_proxy(url):
    """使用随机代理请求"""
    proxy = random.choice(proxy_list)
    try:
        response = requests.get(
            url,
            proxies={"http": proxy, "https": proxy},
            timeout=10
        )
        return response
    except requests.exceptions.ProxyError:
        print(f"代理 {proxy} 不可用，切换至下一个代理")
        return fetch_with_proxy(url)  # 递归重试
```

递归重试需设置重试上限，避免代理池全部失效时无限递归。

### 2.6 异常处理

网络请求存在超时、连接失败、HTTP 错误等多种失败形态，生产环境的爬虫必须包裹完整的异常处理与重试逻辑。

```python
import requests

def safe_request(url, max_retries=3):
    """具备重试能力的请求函数"""
    for i in range(max_retries):
        try:
            response = requests.get(url, timeout=10)

            # 检查状态码
            response.raise_for_status()  # 4xx 或 5xx 会抛出异常
            return response

        except requests.exceptions.Timeout:
            print(f"超时（第 {i+1} 次）")
        except requests.exceptions.ConnectionError:
            print(f"连接失败（第 {i+1} 次）")
        except requests.exceptions.HTTPError as e:
            print(f"HTTP 错误: {e}")
            if response.status_code == 403:
                print("请求被拒绝，需要更换代理")
            elif response.status_code == 429:
                import time
                time.sleep(5)  # 触发限流，等待后继续
            else:
                return None
        except requests.exceptions.RequestException as e:
            print(f"请求异常: {e}")

    return None
```

| 异常类型 | 触发条件 | 常见处理 |
|----------|----------|----------|
| `Timeout` | 超出 timeout 未返回 | 重试或延长超时 |
| `ConnectionError` | DNS 解析失败、连接被重置、代理不可达 | 更换代理后重试 |
| `HTTPError` | `raise_for_status()` 遇到 4xx / 5xx | 按状态码分派策略 |
| `ProxyError` | 代理服务拒绝或无法连通 | 切换代理 |
| `TooManyRedirects` | 重定向次数超过限制 | 检查 URL 与 Cookie |
| `RequestException` | 上述异常的基类 | 兜底捕获，需置于最后 |

**本章要点**：

- **要点**：requests.get/post 返回 Response 对象，`text` 获取文本内容、`content` 获取字节流。
- **要点**：查询参数应通过 `params` 传入，由库自动完成 URL 编码。
- **要点**：超时参数 `timeout` 必须设置，避免请求无限阻塞。
- **要点**：Session 自动维护 Cookie 与公共请求头，登录后的状态保持依赖同一 Session 实例。
- **要点**：`raise_for_status()` 可将非 2xx 响应转为异常，配合重试构成健壮请求的基本形态。

## 3. 数据解析方式

获取 HTML 响应后，核心步骤是**从 HTML 中提取目标数据**。本阶段介绍三种主流解析方式：正则表达式（Regular Expression）、XPath（XML Path Language）、BeautifulSoup。

### 3.1 正则表达式（Regular Expression）

正则表达式是按"模式"匹配文本的工具。在爬虫中适用于：提取结构简单、规则明确的数据，以及文本替换与清洗。

```python
import re

# 基本元字符（掌握以下 8 个可覆盖多数场景）
# .   匹配任意单个字符（换行除外）
# *   前一个字符出现 0 次或多次
# +   前一个字符出现 1 次或多次
# ?   前一个字符出现 0 次或 1 次（也用于非贪婪模式）
# \d  数字（0-9）
# \w  字母/数字/下划线（等价于 [a-zA-Z0-9_]）
# \s  空白字符（空格、制表符、换行）
# []  字符集合，匹配其中任意一个
```

```python
import re

# 简单示例
text = "我的电话是 138-1234-5678，请保存"

# 匹配电话号码
pattern = r"\d{3}-\d{4}-\d{4}"
phone = re.search(pattern, text)
if phone:
    print(phone.group())  # 138-1234-5678
```

```python
import re

# 常用函数
text = "price: 29.9, count: 100, score: 8.5"

# re.findall：找到所有匹配项，返回列表
prices = re.findall(r"\d+\.?\d*", text)
print(prices)  # ['29.9', '100', '8.5']

# re.search：找到第一个匹配，返回 Match 对象
first_num = re.search(r"\d+", text)
print(first_num.group())  # 29

# re.sub：替换匹配的文本
cleaned = re.sub(r"\s", "", text)  # 移除所有空格
print(cleaned)  # "price:29.9,count:100,score:8.5"
```

```python
import re

# 贪婪与非贪婪
html = "<div>内容1</div><div>内容2</div>"

# 贪婪（默认）：尽可能多地匹配
greedy = re.findall(r"<div>(.*)</div>", html)
print(greedy)  # ['内容1</div><div>内容2']  匹配延伸至最后一个 </div>

# 非贪婪：尽可能少地匹配（量词后加 ?）
non_greedy = re.findall(r"<div>(.*?)</div>", html)
print(non_greedy)  # ['内容1', '内容2']  结果符合预期
```

### 3.2 XPath（XML Path Language）— 爬虫主要解析方式

XPath 是通过"路径表达式"在 XML/HTML 文档中定位元素的语言，是爬虫中最常用、效率最高的解析方式，配合 lxml 库使用。

```bash
pip install lxml
```

```python
from lxml import html

# 准备待解析的 HTML
html_str = """
<div class="container">
    <ul id="movie-list">
        <li class="item active">
            <span class="title">流浪地球2</span>
            <span class="score">8.3</span>
        </li>
        <li class="item">
            <span class="title">满江红</span>
            <span class="score">7.4</span>
        </li>
        <li class="item">
            <span class="title">哪吒</span>
            <span class="score">9.0</span>
        </li>
    </ul>
</div>
"""

# 解析 HTML
doc = html.fromstring(html_str)
```

```python
# 核心 XPath 语法（掌握以下内容可覆盖多数场景）

# 1. 基本路径选择
doc.xpath("//li")               # 所有 <li> 元素
doc.xpath("//ul/li")            # <ul> 下的所有 <li>
doc.xpath("/html/body/div")     # 从根开始的绝对路径（不常用）

# 2. 通过属性筛选
doc.xpath("//li[@class='item']")     # class="item" 的 <li>
doc.xpath("//li[@class='active']")   # class 精确匹配
doc.xpath("//*[@id='movie-list']")   # id="movie-list" 的任意元素

# 3. 提取文本
doc.xpath("//li[1]/span[1]/text()")  # 第一个 span 的文本，结果为 ['流浪地球2']

# 4. 提取属性
doc.xpath("//li/@class")             # 所有 <li> 的 class 属性值，结果为 ['item active', 'item', 'item']

# 5. 位置和索引
doc.xpath("//li[1]")                 # 第一个 <li>（索引从 1 开始）
doc.xpath("//li[last()]")            # 最后一个 <li>
doc.xpath("//li[last()-1]")          # 倒数第二个
doc.xpath("//li[position()>1]")      # 从第二个开始往后的所有节点

# 6. 条件组合
doc.xpath("//li[@class='item' and .//span[contains(text(),'哪吒')]]")
# class="item" 且子元素中包含"哪吒"文本的 <li>

# 7. 模糊匹配
doc.xpath("//span[contains(@class, 'title')]/text()")  # class 包含 "title" 的 span
doc.xpath("//span[starts-with(@class, 'tit')]/text()") # class 以 "tit" 开头的 span

# 8. 轴定位（处理复杂层级关系）
doc.xpath("//span[text()='8.3']/../span[1]/text()")
# 定位文本为"8.3"的 span，向上取父节点，再取父节点下的第一个 span 的文本
```

```python
# 爬虫实战：完整提取所有电影信息

# 方式 1：分别提取
titles = doc.xpath("//li/span[@class='title']/text()")
scores = doc.xpath("//li/span[@class='score']/text()")
for t, s in zip(titles, scores):
    print(f"{t}: {s}分")

# 方式 2：遍历每个 li 逐个提取（推荐，结构清晰且不易错位）
for li in doc.xpath("//li"):
    title = li.xpath("span[@class='title']/text()")[0]
    score = li.xpath("span[@class='score']/text()")[0]
    print(f"{title}: {score}分")
```

两种方式的差异在于数据对应关系：方式 1 依赖各字段数量完全一致，字段缺失时 `zip` 会造成整体错位；方式 2 以节点为单位提取，缺失字段可单独处理。

**XPath 常用语法速查：**

```text
//        任意位置             /         直接子节点
@         属性                 text()    文本内容      [n]  第 n 个节点
contains  模糊匹配             starts-with  前缀匹配
```

### 3.3 BeautifulSoup（bs4）— 容错性高的解析方式

BeautifulSoup 适合 HTML 不规范、结构混乱的页面。其执行速度慢于 lxml，在数据量较小的项目中使用更为合适。

```bash
pip install beautifulsoup4 lxml
```

```python
from bs4 import BeautifulSoup

html_str = """
<div class="container">
    <ul id="movie-list">
        <li class="item active">
            <span class="title">流浪地球2</span>
            <span class="score">8.3</span>
        </li>
        <li class="item">
            <span class="title">满江红</span>
            <span class="score">7.4</span>
        </li>
    </ul>
</div>
"""

# 解析（第二个参数指定解析器，使用 lxml 时速度更快）
soup = BeautifulSoup(html_str, "html.parser")  # 内置解析器，无需额外安装
# soup = BeautifulSoup(html_str, "lxml")  # 速度更快，需要 pip install lxml
```

```python
# 1. 通过标签名查找
soup.find("li")           # 第一个 <li>
soup.find_all("li")       # 所有 <li>，返回列表

# 2. 通过属性查找
soup.find("li", class_="item")           # class="item" 的 <li>（class_ 带下划线，避免与关键字冲突）
soup.find("li", attrs={"class": "item"}) # 通用属性写法
soup.find(id="movie-list")               # id="movie-list" 的元素

# 3. CSS 选择器（推荐，与前端书写习惯一致）
soup.select("li")                          # 所有 <li>
soup.select(".item")                       # class="item" 的元素
soup.select("#movie-list")                 # id="movie-list" 的元素
soup.select("ul > li")                     # 直接子节点
soup.select("li.item")                     # <li class="item">
soup.select("li:first-child")              # 第一个 <li>
soup.select("li:nth-of-type(2)")           # 第二个 <li>
```

```python
# 4. 提取文本和属性
item = soup.find("li")
print(item.text)                    # 全部文本（含子元素）→ "流浪地球28.3"
print(item.get_text(strip=True))    # 去除首尾空白
print(item.get_text(separator="|")) # 自定义分隔符 → "流浪地球2|8.3"

# 提取 class 属性
print(item.get("class"))            # ['item', 'active']
print(item["class"])                # 结果同上，属性不存在时抛出异常

# 5. 节点关系
item = soup.find("li")
print(item.parent)             # 父节点（<ul>）
print(item.parents)            # 所有祖先节点（生成器）
print(item.children)           # 直接子节点（生成器），不可用 len() 判断数量
print(item.contents)           # 直接子节点（列表）
print(item.next_sibling)       # 下一个兄弟节点（第二个 li）
print(item.previous_sibling)   # 上一个兄弟节点（None，当前为首个节点）
```

```python
# 爬虫实战：提取所有电影信息
movies = []
for li in soup.select("li"):
    title = li.find("span", class_="title").text
    score = li.find("span", class_="score").text

for m in movies:
```

### 3.4 三种解析方式对比

| 特性 | 正则表达式（re） | XPath（lxml） | BeautifulSoup |
|------|------------------|---------------|---------------|
| 学习曲线 | 陡峭 | 中等 | 平缓 |
| 执行速度 | 最快 | 快 | 较慢 |
| 容错性 | 低 | 中 | 高 |
| 是否依赖 HTML 结构 | 不依赖 | 依赖 | 依赖 |
| 适用场景 | 提取规则简单的数据 | 结构清晰的页面 | 结构混乱的页面 |
| **爬虫中的定位** | 辅助工具 | **主要方案** | 备选 |

**本章要点**：

- **要点**：正则表达式适合提取规则明确的数据，需区分贪婪与非贪婪模式，跨行匹配依赖 `re.DOTALL`。
- **要点**：XPath 是爬虫的主要解析方案，索引从 1 开始，支持属性筛选、模糊匹配与轴定位。
- **要点**：BeautifulSoup 容错性最高，适合结构不规范的页面，但速度低于 lxml，`find` 与 `select` 是两类基本查找入口。
- **要点**：三种方式常组合使用，以 XPath 为主、正则表达式与 BeautifulSoup 为辅。

### 4.1 项目一：抓取豆瓣电影 Top250（综合练习）

该项目覆盖 requests 请求、XPath 解析与 CSV 存储的完整链路。

```python
"""
抓取豆瓣电影 Top250，提取电影名、评分、评价人数、经典台词
练习内容：requests + XPath + CSV 保存
"""
import requests
from lxml import html
import csv
import time


def fetch_page(page):
    """请求单页"""
    url = f"https://movie.douban.com/top250?start={(page-1)*25}"
    headers = {
        "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
        "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8",
        "Accept-Language": "zh-CN,zh;q=0.9,en;q=0.8",
    }

    # 说明：豆瓣存在反爬策略，此处使用 mock 数据演示逻辑
    # 实际使用时需考虑代理、Cookie 等因素
    print(f"正在抓取第 {page} 页...")
    # response = requests.get(url, headers=headers, timeout=10)
    # response.encoding = "utf-8"
    # return response.text

    # mock 数据（结构与豆瓣的 HTML 一致）
    return f"""
    <ol class="grid_view">
        <li>
            <div class="item">
                <div class="info">
                    <span class="title">电影{page}A</span>
                    <div class="bd">
                        <span class="rating_num">9.{page}</span>
                        <span>评价: {10000 + page*100}人</span>
                        <span class="inq">经典台词{page}</span>
                    </div>
                </div>
            </div>
        </li>
        <li>
            <div class="item">
                <div class="info">
                    <span class="title">电影{page}B</span>
                    <div class="bd">
                        <span class="rating_num">8.{page}</span>
                        <span>评价: {8000 + page*100}人</span>
                        <span class="inq">经典台词{page}B</span>
                    </div>
                </div>
            </div>
        </li>
    </ol>
    """


def parse_page(html_text):
    """解析单页的 HTML"""
    doc = html.fromstring(html_text)
    movies = []

    for item in doc.xpath("//li"):
        title = item.xpath(".//span[@class='title']/text()")
        score = item.xpath(".//span[@class='rating_num']/text()")
        quote = item.xpath(".//span[@class='inq']/text()")

        if title:  # 过滤无标题的空项
            movies.append({
                "title": title[0] if title else "",
                "score": score[0] if score else "",
                "quote": quote[0] if quote else "",
            })

    return movies


def save_to_csv(movies, filename="douban_top250.csv"):
    """保存为 CSV 文件"""
    with open(filename, "w", encoding="utf-8-sig", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=["title", "score", "quote"])
        writer.writeheader()
        writer.writerows(movies)
    print(f"已保存 {len(movies)} 条数据到 {filename}")


def main():
    all_movies = []

    for page in range(1, 11):  # Top250 共 10 页
        html_text = fetch_page(page)
        movies = parse_page(html_text)
        all_movies.extend(movies)
        time.sleep(1)  # 设置请求间隔，避免对服务器造成压力

    save_to_csv(all_movies)
    print("抓取完成")


if __name__ == "__main__":
    main()
```

实现细节说明：

| 细节 | 处理方式 | 原因 |
|------|----------|------|
| 翻页 | URL 中的 `start` 偏移量，`(page-1)*25` | 豆瓣列表页按偏移量分页，每页 25 条 |
| 编码 | `encoding="utf-8-sig"` | 避免 Excel 打开 CSV 时中文乱码 |
| 空值 | `title[0] if title else ""` | XPath 结果为列表，属性缺失时返回空列表 |
| 请求间隔 | `time.sleep(1)` | 控制频率，降低被限流与封禁的风险 |

### 4.2 项目二：模拟登录（Session 练习）

该项目练习 Session、POST 提交与登录后的状态保持。

```python
"""
模拟登录网站并获取登录后的数据
练习内容：Session + POST + 状态保持
"""
import requests


class LoginSimulator:
    """模拟登录器"""

    def __init__(self, base_url):
        self.session = requests.Session()
        self.base_url = base_url.rstrip("/")
        # 配置为浏览器形态的请求头
        self.session.headers.update({
            "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
        })

    def login(self, username, password):
        """提交登录请求"""
        # 实际场景中可能需要先 GET 登录页以获取 csrf_token
        login_data = {
            "username": username,
            "password": password,
            "remember_me": "1",
        }

        resp = self.session.post(
            f"{self.base_url}/login",
            data=login_data,
            timeout=10
        )

        # 判断登录是否成功
        # 实践中可检查响应中是否包含登录成功提示，或 Cookie 中是否存在特定字段
        if resp.status_code == 200:
            print("登录成功")
            return True
        else:
            print(f"登录失败: {resp.status_code}")
            return False

    def get_profile(self):
        """获取登录后的个人信息"""
        resp = self.session.get(
            f"{self.base_url}/my/profile",
            timeout=10
        )
        return resp.text

    def get_orders(self):
        """获取登录后的订单列表"""
        resp = self.session.get(
            f"{self.base_url}/my/orders",
            timeout=10
        )
        return resp.text
```

**本章要点**：

- **要点**：完整抓取流程由分页请求、单页解析、数据汇总与结构化存储四个步骤构成。
- **要点**：CSV 保存使用 `utf-8-sig` 编码，可避免 Excel 打开时中文乱码。
- **要点**：XPath 提取结果为列表，字段缺失时需以条件表达式兜底，防止索引越界。

## 5. 实践建议

1. **以 XPath 为主要解析方案，正则表达式与 BeautifulSoup 为辅助**：优先掌握 XPath，可满足约 80% 的提取需求；正则表达式用于简单文本处理，BeautifulSoup 用于结构不规范的页面。
2. **使用 Chrome DevTools 验证 XPath**：在浏览器 Console 中输入 `$x("//目标 XPath")` 即可测试表达式结果，无需每次执行完整代码。
3. **请求头是反爬虫的第一道检查项**：多数网站在配置规范的 User-Agent 后即可正常访问。
4. **必须设置 timeout**：未设置超时的请求可能使爬虫长时间阻塞。
5. **遵守 robots.txt 约定**：抓取前访问 `https://example.com/robots.txt`，确认禁止抓取的路径。

**本章要点**：

- **要点**：解析方式的学习顺序为 XPath 优先、正则表达式与 BeautifulSoup 次之。
- **要点**：在浏览器 Console 中以 `$x()` 验证 XPath，可显著提升编写效率。
- **要点**：请求头配置与超时设置是爬虫稳定运行的两项基础保障。
- **要点**：抓取行为需遵守 robots.txt 与目标站点的访问频率约定。

## 阶段小结

| 知识模块 | 核心要点 | 在爬虫中的作用 |
|----------|----------|----------------|
| 请求-响应模型 | 客户端发起请求、服务器返回响应；HTTPS 在 HTTP 之上增加 TLS 加密 | 理解所有请求库的底层行为 |
| 请求方法 | GET 获取资源、POST 提交数据，PUT/PATCH/DELETE 较少使用 | 决定参数位置与请求体构造方式 |
| 请求头 | User-Agent、Referer、Cookie、Accept、Authorization 等字段 | 通过站点的合法性检查，避免 403 |
| 状态码 | 2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务器错误 | 决定解析、重试、换代理等分支行为 |
| requests 基本用法 | get/post、params、json/data、timeout、encoding | 获取页面与接口数据的主要入口 |
| Session 会话 | 自动维护 Cookie 与公共请求头 | 实现模拟登录与登录后数据抓取 |
| 代理与异常处理 | proxies 配置、轮换代理、Timeout/HTTPError 分类捕获 | 绕过 IP 限制，保障长时间任务稳定运行 |
| 正则表达式 | 元字符、findall/search/sub、贪婪与非贪婪、分组 | 提取规则简单的文本与数据清洗 |
| XPath（lxml） | 路径选择、属性筛选、索引、模糊匹配、轴定位 | 爬虫的主要解析方案 |
| BeautifulSoup | find/find_all、CSS 选择器、文本与属性提取、节点关系 | 解析结构混乱的页面 |
| 实战项目 | 分页请求 + XPath 解析 + CSV 存储；Session 模拟登录 | 将各知识点组合为完整抓取链路 |

## 常见问题与排查

| 现象 | 原因 | 处理方式 |
|------|------|----------|
| 请求返回 403 | 未设置 User-Agent 或请求头形态明显非浏览器 | 配置真实浏览器 User-Agent 与 Accept 系列字段，必要时更换代理 |
| 响应中文显示乱码 | `response.encoding` 自动检测结果与页面实际编码不一致 | 在读取 `text` 前手动设置 `response.encoding = "utf-8"` |
| 登录后再次请求仍需登录 | 未复用 Session，Cookie 未在请求间持久化 | 使用同一 `requests.Session()` 实例发送登录与后续请求 |
| 请求长时间无返回 | 未设置 timeout，连接处于无限阻塞状态 | 设置 `timeout`，可传入单值或 `(连接超时, 读取超时)` 元组 |
| 连续请求后返回 429 | 请求频率超过站点限流阈值 | 加入请求间隔、降低并发，等待后重试 |
| 正则提取结果包含多余标签 | 默认贪婪模式使匹配延伸至最后一个闭合标签 | 使用非贪婪写法 `(.*?)` |
| XPath 提取报 IndexError | 目标字段在该节点中不存在，返回空列表 | 先判断结果是否为空，或使用条件表达式取值 |
