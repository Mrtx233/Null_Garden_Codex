# Anglan Crawler JSON｜采集、分析与定价工作台

## 项目定位

这是我将 Shopify 商品采集、数据整理、定价与平台导出整合为四阶段流程的本地工作台。商品原始信息先保存为 JSON，再转换为十字段 Excel，使采集、规则分析和价格方案可以分别重跑。

仓库保留两个可独立运行的版本：05 用于旧规则对照，06 使用新定价方案并重构了调度、配置与阶段步骤。

本篇结合仓库说明、06 调度器、价格匹配和报告模块整理，阅读日期为 **2026 年 10 月 3 日**。仓库当前为私有仓库，源码链接需要访问权限。

## 四阶段流程

| 阶段          | 输入                        | 输出                                        |
| ------------- | --------------------------- | ------------------------------------------- |
| 01 链接采集   | 分类名称与 Shopify 分类 URL | 域名商品链接 JSON、链接索引                 |
| 02 商品采集   | 项目中的商品链接文件        | 商品详情汇总 JSON                           |
| 03 数据分析   | 商品详情汇总                | 十字段 Excel                                |
| 04 价格与导出 | 十字段 Excel 或源表目录     | 合并表、原价表、匹配表、平台 CSV 与定价报告 |

工作台可以串行执行选中的阶段，也可以只处理已有数据。单独选择一个阶段不会补跑其前置阶段。

## 商品数据整理

阶段二保留商品地址、标题、分类、描述 HTML、售价、划线价、图片、选项统计和变体选项，另可保存币种。

阶段三将其整理成与 Anglan 系列共享的十字段结构：

```text
title, name, price1, price2, styles1, styles2, styles3, src_links, link-href, details
```

处理选项包括图片位置筛选、颜色数量上限、尺码维度开关和颜色图片整理。Color 上限用于拆分多颜色商品行，Size 开关控制是否导出该维度。

款式串中的特殊字符使用对称转义与解码规则，避免选项值本身含有分隔符时破坏变体结构。

阶段三仅导出已确认的 USD 价格。币种或换算无法确认的商品进入失败记录；阶段四直接使用 Excel 中已有金额，不负责重新识别币种。

## 05 与 06 的定价差异

| 行为         | 05                     | 06                             |
| ------------ | ---------------------- | ------------------------------ |
| 参考价格     | 划线价优先，缺失时售价 | 采集售价优先，缺失时采集划线价 |
| 分配方式     | 按参考价顺序逐行取价   | 整批候选关系分析与增广调整     |
| 同款价差控制 | 无独立上限             | 默认最高价 / 最低价不超过 1.10 |
| 价格档数     | 随尺码数量分配         | 默认每款最多 3 档              |
| 跨商品复用   | 已分配库价不再使用     | 覆盖后可为剩余商品受控复用     |
| 报告         | 未分配价格清单         | 商品、库价与汇总报告           |

06 会先建立商品与库价的候选关系，优先分配候选商品较少的价位，在搜索预算内调整已有分配，并同时检查价差和档数限制。

这是受约束的全局启发式方案，不保证数学最优，也不保证价格库全部被覆盖。没有合适候选商品的价位需要更换数据或调整允许范围。

## 定价报告与导出

阶段四分别保留原价和匹配后的 Shopify CSV，并转换为 WooCommerce CSV。06 增加：

- 商品定价明细：记录参考价、匹配状态与处理原因。
- 价格库覆盖明细：说明价位是否覆盖及相关候选情况。
- 定价汇总 JSON：供整体检查与后续分析。

匹配表保留采集售价、划线价和原始款式等依据。重复尝试定价时可以继续使用采集依据，降低将上次匹配价格误当原价的风险。

## 目录与运行状态

```text
Anglan_Crawler_Json/
├── 05Json Crawler system/    旧版工作台
├── 06Json Crawler system/    新版工作台
├── ANG_OUTPUT_XLSX/          项目数据与产物
├── Utils/                   独立工具
└── requirements.txt
```

每个店铺项目根目录下组织 `Json/`、`Json/Data Analysis/`、`Xlsx/`、`原价/` 与 `价格匹配/`。工作台应选择这些目录的共同父目录。

任务区分成功、部分成功、失败和用户停止。失败清单与有效产物可以同时存在，“继续后续阶段”不代表前一阶段的问题已经解决。

关键产物通过同目录临时文件原子替换；该保障针对单个文件，并非整批导出事务。

## 环境与启动

使用 Python 3.10+、Tkinter 和 Chromium 系浏览器。依赖安装与两个版本入口为：

```bash
python3 -m pip install -r requirements.txt
python3 "06Json Crawler system/main_06.py"
```

需要对照旧规则时：

```bash
python3 "05Json Crawler system/main_05.py"
```

06 定价算法使用现有依赖与 Python 标准库，不需要额外优化求解器。已有十字段 Excel 时可以直接运行阶段四。

## 当前边界与实践价值

本项目的实践重点是可重跑的中间数据、阶段独立执行、定价约束与报告反馈。两个版本使用相似产物名称，比较结果时应使用不同项目副本。

阶段三拆色后的每一行是独立定价单位，阶段四不会按原商品链接自动合并为同一个定价组。工作台暂无保留的统一自动化测试套件，本篇没有执行真实采集或定价验收。
